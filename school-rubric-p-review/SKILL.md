# School Rubric P Review

## 目的

与えられたルーブリックを構造化し、提出物の根拠に基づいて各観点を判定し、最終的に `P` と `総評` を出力する。

## 入力確認

次を最初に確認する。

- ルーブリック（画像またはテキスト）
- 評価対象の提出物（本文、要約、画像、資料、抜粋）
- 採点条件（再提出可否、厳しめ/標準、文字数制約）

ルーブリックが画像で判読困難な場合は、判読不能箇所を明示し、必要ならテキスト化を依頼する。

## 評価ワークフロー

1. ルーブリックを観点単位で整理する。
2. 各観点について「達成レベル」「配点/重み」「判定条件」を抜き出す。
3. 提出物から観点ごとの根拠を拾い、該当レベルを判定する。
4. 観点別判定を統合して最終 `P` を決める。
5. 根拠付きの総評を作成する。

## Pの決定ルール

次の優先順位で `P` を決定する。

1. ルーブリックに `P` の定義がある場合は、その定義を厳守する。
2. ルーブリックに合計点ルールがある場合は、その合計点を `P` とする。
3. 集計ルールがない場合は、観点レベルを線形換算して暫定 `P` を算出し、`暫定` と明記する。

線形換算の既定:

- 各観点の最低レベルを `0`、最高レベルを `1`
- 重みがあれば重み付き平均、なければ単純平均
- `P = 平均 * 100`（整数丸め）

## 出力フォーマット

常に次の形式で返す。

```markdown
P: <値>  （必要に応じて「暫定」表記）

総評:
<2-5文。強み、改善点、次に直す優先事項を含める>

観点別根拠:
- <観点名>: <判定レベル> / 根拠: <提出物の具体的記述>
- <観点名>: <判定レベル> / 根拠: <提出物の具体的記述>

不足情報:
- <不足がある場合のみ列挙。なければ「なし」>
```

## 品質基準

- 根拠なし判定をしない。
- ルーブリック外の基準を勝手に追加しない。
- 断定が難しい箇所は「推定」と明記する。
- 1つ以上の改善提案を、実行可能な行動で示す。
