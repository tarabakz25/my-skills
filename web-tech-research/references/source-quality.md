# Source quality rubric

目的: Web 上の情報を「信頼できる順」に扱い、結論の不確実性を下げる。

## 優先順位（高 → 低）

1. 公式一次情報
   - 公式ドキュメント、公式ブログ、公式リポジトリ（Releases/Tags/CHANGELOG）
   - 公式 Pricing / Support policy / Lifecycle policy
2. 仕様・標準
   - RFC、標準化団体、正式な仕様書
3. セキュリティ一次情報
   - ベンダーアドバイザリ、CVE（NVD / GitHub Security Advisory 等）
4. 二次情報（補助）
   - 信頼できるメディア、著名コミュニティ、カンファレンス資料
5. 低優先（参考程度）
   - 個人ブログ、SNS、AI 要約のみのページ

## 取り扱いルール

- 公式一次情報が見つかったら、それを結論の根拠にする（ブログ等は補助に回す）
- 情報が食い違う場合は、両方を併記して「なぜズレるか」を推測ではなく根拠ベースで説明する
- “最終更新日/公開日” を確認し、古い情報は古いと明記する
- 価格・規約・サポート期限は変わりやすいので、必ず日付付きで記載する
