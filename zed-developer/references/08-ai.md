# AI in Zed

## Identify the surface

- Zed Agent: native tool-using coding agent in Agent Panel.
- Inline Assistant: inline edits with explicit context.
- Edit Prediction: per-keystroke predictive edits.
- External Agents: ACP-connected agents; auth, tools, instructions, and data terms may differ.
- Terminal Threads: CLI/TUI owns its environment and behavior.
- MCP: additional tools/data sources.
- Skills: reusable on-demand instruction packages for Zed Agent.
- Instructions: always-on personal/project guidance.
- Agent Profiles: choose available tools; permissions separately decide allow/deny/confirm.

Do not transfer assumptions between these surfaces.

## Zed Skills (usage knowledge)

Zed-native skills live as direct children of:

- Global: `~/.agents/skills/<name>/SKILL.md`
- Project: `<worktree>/.agents/skills/<name>/SKILL.md`

Zed's discovery is flat at the skills root; project skills require a trusted worktree. Global/project name collision favors project. Frontmatter requires `name` and `description`; `disable-model-invocation: true` leaves manual slash/mention invocation while removing autonomous catalog use. Keep `SKILL.md` focused and detailed files in `references/`. This is separate from the current package, which is Cursor-specific and lives under `.cursor/skills/`.

## Instructions

Personal:

- macOS/Linux: `~/.config/zed/AGENTS.md`
- Windows: `%APPDATA%\Zed\AGENTS.md`

Project instructions use the first matching recognized compatibility file in documented order, including `.rules`, `.cursorrules`, `.windsurfrules`, `.clinerules`, `.github/copilot-instructions.md`, `AGENT.md`, `AGENTS.md`, `CLAUDE.md`, and `GEMINI.md`. Project instructions override conflicting personal instructions. External agents may load their own native files independently.

Use Skills for reusable/on-demand procedures; use Instructions for always-on behavior. Avoid huge always-on files.

## MCP and external agents

For MCP configuration:

1. Prefer registry/UI installation where supported.
2. Review server source, command, arguments, environment access, and network destinations.
3. Store credentials using the server/provider's secure mechanism, never committed JSON.
4. Use tool permissions and least-privilege profiles.
5. For remote projects, decide whether the MCP server executes locally or remotely and where credentials exist.

Zed extension-packaged MCP servers are planned for deprecation in favor of the official MCP registry at the baseline. Do not start a new marketplace MCP extension without checking current policy.

External agents via ACP have their own sign-in, subscription, configuration, instructions, MCP, and data handling. Debug ACP with `dev: open acp logs`; redact sensitive content before sharing.

## Tool safety

Agent Profiles determine available tools, not automatic permission. Tool Permissions control allow/deny/confirm. Never recommend blanket approval for shell, file write, network, or MCP tools merely for convenience. Keep project trust enabled and review cloned project instructions/skills before activation.

## Disable/minimize AI

`disable_ai` can disable native AI features globally; `edit_prediction_provider: "none"` can disable edit prediction at the applicable baseline. Verify current settings. External agents/terminal CLIs may continue to operate independently.
